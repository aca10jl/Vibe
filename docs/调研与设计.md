# 「一键一生」AI 伴读助手 — 调研与方案设计

> 面向半导体 Wafer 良率根因分析的 HTML 平台，在页面右侧引入 AI 助手，
> 用于**分析页面内容、指引用户正确提交「一键一生」任务、并以智能体技术持续学习用户习惯**。

---

## 1. 需求拆解

| 诉求 | 含义 | 设计落点 |
|---|---|---|
| 分析页面内容 | AI 能"看懂"当前 HTML 上的场景配置与结果 | **Context Collector**：把 DOM 状态 + 计算结果结构化为上下文快照 |
| 指引正确提交任务 | 校验填表、补全/修正、再提交 | **校验器 + 工具调用**：`set_scenario` / `set_analysis_dims` / `run_lifecycle` |
| AI 伴读 / 分析 / 建议 | 三种助手能力 | 三个意图通道 `companion / analyze / advise` |
| 智能体技术 | 不只是聊天，能**操作页面** | **前端工具注册表**（function-calling 落到真实 DOM 动作） |
| 持续学习用户习惯 | 沉淀个性化画像 | **Habit Profile**：行为埋点 → localStorage 画像 → 个性化默认值/建议 |

---

## 2. 技术方案调研（选型对比）

### 2.1 AI 能力承载方式

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **A. 纯前端规则引擎** | 零依赖、零密钥、离线可跑、零成本、可控 | 泛化弱、不能自由对话 | ✅ 作为 **Demo 默认模式 / 兜底** |
| **B. 直连 LLM API（浏览器）** | 简单 | **密钥暴露**、CORS、无法注入业务工具执行 | ❌ 不安全 |
| **C. 后端代理 + LLM（Claude）** | 密钥安全、可注入领域系统提示与工具、可审计 | 需服务端 | ✅ 作为**生产/在线模式** |
| D. 浏览器本地小模型(WebLLM) | 隐私 | 体积大、能力有限 | 备选 |

> **采用 A + C 双模**：前端默认 **本地推理**（保证 Demo 一键可跑），一个开关切换到 **Claude 在线**（后端 `/api/chat` 代理到 `claude-opus-4-8`，带工具调用）。两种模式**统一返回结构** `{text, toolCalls, followups}`，对 UI 透明。

### 2.2 「智能体」实现路径

AI 助手要真正"指引操作页面"，关键是 **工具调用（function/tool calling）**：

```
用户/意图 ──▶ LLM（带页面上下文 + 工具schema） ──▶ {文本 + tool_use}
                                                      │
                          前端 AgentTools.execute ◀───┘  真正改 DOM：
                          set_scenario / set_analysis_dims /
                          run_lifecycle / focus_panel / apply_my_habits
```

- **Claude 模式**：复用 Messages API 原生 `tools` 参数，解析返回的 `tool_use` 块。
- **本地模式**：规则引擎产出同样的 `toolCalls` 数组。
- 工具 schema **单一来源**（`tools.js`），同时喂给 Claude 与本地引擎，避免双份维护。

> 对应 Anthropic 文档的"用户自定义工具 + 客户端执行循环"。Demo 采用**单轮**（模型给动作→前端执行→可继续追问），生产可升级为多轮 agentic loop 或 Managed Agents。

### 2.3 「持续学习用户习惯」实现路径

| 层级 | 做法 | 本 Demo |
|---|---|---|
| 行为采集 | 对配置变更、提交、面板聚焦、意图埋点 | ✅ `HabitProfile.track()` |
| 画像沉淀 | 计数 + 排序 → 偏好（常用 Fab/节点/维度/意图） | ✅ localStorage 持久化 |
| 个性化反哺 | 一键套用习惯默认值；建议中引用画像 | ✅ `apply_my_habits` / advise 引用 |
| 进阶（生产） | 服务端用户画像、在线学习、RLHF 信号、记忆库 | 文档给出路径（Claude Memory Tool / Memory Stores） |

模块职责：

## 4. 领域建模（让 Demo 有"半导体味"）

**晶圆一生链路**：前道(光刻→刻蚀→注入→沉积→CMP) → 中测(WAT/CP) → 后道(封装/FT)。

**根因分析维度**：设备/腔体关联(commonality)、工艺步骤、参数漂移(WAT SPC)、缺陷空间特征、批次谱系。

**缺陷空间特征 ↔ 根因环节**（数据生成时按此注入"真相"，使分析自洽）：

| 缺陷特征 | 空间形态 | 高概率根因环节 |
|---|---|---|
| Edge Ring 边缘环 | 边缘失效带 | 边缘刻蚀 / 清洗 / 膜厚均匀性 |
| Center 中心聚集 | 圆心失效 | CMP / 旋涂 / 温场中心 |
| Scratch 划伤 | 斜线 | 机械搬运 / CMP 研磨 |
| Cluster 局部簇 | 局部团 | 腔体颗粒污染 / 气体异常 |

> 因此 Demo 中"中心聚集→CMP 设备"等结论是**领域自洽**的，而非随机文本。

## 5. AI 三大能力的具体设计

- **伴读（Companion）**：读取上下文，区分"配置中/已出结果"两态，逐面板讲解含义与当前状态；提交后自动触发一次伴读。
- **分析（Analyze）**：基于 commonality 打分输出**按关联度排序的根因候选 + 结论 + 置信度**；无结果时先帮助提交。
- **建议（Advise）**：未就绪→列出校验问题并用工具**一键修正**；已就绪→引导提交；已出结果→给出隔离/复测/扩样等**处置动作**。

**Prompt 设计（Claude 模式）**：系统提示 = 角色定义 + 领域知识 + 工具使用约束 + **实时页面上下文 JSON** + 习惯画像；明确"意图明确时优先用工具完成动作、不可编造数值"。

---

## 6. 安全与生产化考量

- 密钥仅在后端；前端零密钥即可 Demo。
- 工具为**白名单**、仅限页面内安全动作（无破坏性操作）；生产中破坏性动作应加二次确认（参考 agent-design：可逆性/审批门）。
- 上下文只传必要的派生摘要，避免敏感原始数据外泄。
- 习惯画像本地存储，生产可迁移服务端并做合规（PII/留存策略）。

---

## 7. 演进路线（Roadmap）

1. **数据接入**：用 MES/YMS/EDA 真实数据替换 `mockData.js`（保持同一 schema）。
2. **多轮智能体**：升级为 agentic loop / **Claude Managed Agents**，支持长任务、文件产出（报告/图表）。
3. **跨会话记忆**：接 Claude **Memory Tool / Memory Stores**，把习惯画像升级为持久记忆。
4. **流式体验**：后端改 SSE 流式输出，前端逐字渲染。
5. **RAG/知识**：接入 SOP/历史 FA 报告，做检索增强的根因建议。
6. **闭环**：把用户对建议的采纳/否决回流为在线学习信号。
